Write Solana programs in Python.

PythSol checks a typed Python subset, lowers it to C, and compiles native SBF bytecode — with an Anchor-style IDL, a solders client, and LiteSVM tests. Nothing here runs your code.

From .py to .so, checked at every step

Each stage draws on the same checked definition of your program — no phase re-parses it with different rules.

Write

Instructions, accounts, errors in one .py. → program.py

Check

PSxxxx diagnostics with file, line, column. → a clean list, or a fix

Emit C

Readable C with runtime checks, per source line. → program.c

Build .so

Native SBF via Solana clang — cached, byte-identical. → program.so

Ship

Anchor-style IDL + solders client + manifest. → your client

You write — from examples/counter/programs/counter.py

counter.py
@instruction
def increment(authority: Signer, counter: Mut[Counter], by: u64) -> None:
    """Add `by` to the count; only the stored authority may call this."""
    require(counter.authority == authority.key, CounterError.Unauthorized)
    counter.count += by

The compiler writes

counter.c — excerpt
static uint64_t pyf_increment(RtCtx *rt) {
    /* (data-length checks: omitted in this excerpt) */
    /* 2. accounts: 2 role-checked in declared order */
    RtAccount *acc_authority = &rt->accounts[0u];
    if (!acc_authority->is_signer) {
        rt_fail_log(1001u, "counter.py", 49u, "signer required: authority");
        return 1001u;
    }
    /* … writable, owner, size, and discriminator checks follow … */
    uint64_t rt_t2 = 0u;
    rt_ld_u64(acc_counter->data, 40u, &rt_t2);
    uint64_t rt_t3;
    uint64_t rt_t4 = rt_checked_add_u64(rt_t2, dp_by, &rt_t3);
    if (rt_t4 != RT_OK) {
        rt_fail_log(rt_t4, "counter.py", 52u, "checked add (u64)");
        return rt_t4;
    }
    rt_st_u64(acc_counter->data, 40u, rt_t3);
    return 0u; /* RT_OK */
}

Both chunks are real: the Python lines are the increment instruction from examples/counter, and the C is what the compiler emits for them — accounts role-checked, discriminator verified, arithmetic overflow guarded, every failure attributed to a source line. What PythSol is

  • A typed Python subset that a compiler can lower to C and native SBF bytecode.
  • A checker with stable PSxxxx diagnostics that carry file, line, and column.
  • A generator for an Anchor-style IDL, a solders client, and a build manifest.
  • A test runner — real bytecode in LiteSVM, offline and fast.

What it isn't

  • Not all of Python — no async, no comprehensions, no f-strings, no stdlib imports on-chain.
  • Not an interpreter: the site parses and type-checks, it never executes your Python.
  • No in-browser SBF compile — .so builds run where Solana's clang lives (your machine or Docker).
  • Not on PyPI yet — install from the repository.

Questions worth asking

Does this site run my Python?

No. The playground sends your source to a checker that parses it and reports PSxxxx diagnostics. Emitting C is a pure transformation of the checked AST. Compiling to .so happens only on a machine with the SBF tools — loopback pythsol serve, Docker, or your workstation.

What's in the typed subset?

Annotated integers u8–u128 and i8–i128, bool, Pubkey, Signer, Mut/Init/Account, FixedArray, Option, FixedString, capacity-carrying Vec[T, N], unit @enum with match, @struct, @event + emit, plain helpers, and if/while/for over range. Compiler-known calls are require, len, range, emit, system_transfer, token_transfer, token2022_transfer, ata_create, and the width casts. Stdlib and third-party imports are refused. Full details on the Language page.

What does pythsol build write?

The generated C, the native SBF .so, an Anchor-style IDL, a solders client, and a manifest.json that ties them together. Rebuilds are cached and byte-identical for the same source.

How do tests run without a validator?

pythsol test executes the real program bytecode in-process through LiteSVM — no validator, no RPC, no airdrop. The four shipped examples all pass.

Can I deploy to mainnet?

pythsol deploy defaults to devnet. The CLI refuses mainnet unless you pass --yes, and the faucet never touches it. pythsol verify compares the on-chain bytecode against your local .so by hash.
