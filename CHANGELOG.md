# Changelog

PythSol follows Keep a Changelog; before 1.0 every breaking change is listed under **Breaking**.

## [Unreleased]
### Added
- Phase 4 — the C emitter lowers `if`/`elif`/`else`, `while` (including `else`), `for x in range(...)`, `break`, `continue`, bare `return`, expression-level checked arithmetic, shifts, bitwise ops, width casts such as `u64(x)` (narrowing aborts with 1009), and `FixedArray[scalar, N]` fields and locals. Integer widths through `u128`/`i128` are accepted.
- Phase 5 — `pythsol build` writes `{name}_client.py`: solders `Instruction` builders and account decoders. Generated clients do not import the compiler. A signer on an `Init` instruction is marked writable, and the System program account is appended, so `initialize` can pay for the PDA.
- Phase 6 — `pythsol init DIR --template counter|ledger` scaffolds `pysol.toml`, `pyproject.toml`, a README, and `programs/<name>.py`. `pythsol idl PROGRAM.py` prints the IDL without the SBF toolchain.
- `examples/ledger`: deposits into a fixed slot array, an `if`/`else` apply, and a `for`-range fill. LiteSVM covers deposit → apply → fill, unauthorized (6000), and a bad slot (6001).
- Unit enums — `@enum` classes whose variants are `Name = <index>` (the Anchor tag, one byte). Fields, locals, instruction arguments, and `FixedArray` elements of a unit enum keep fixed offsets. `match` is exhaustive (every variant, or a final `_`). A byte that is not a variant aborts with 1011. Data enums stay rejected. The generated client exports `STATUS_OPEN = 0` style constants, and the IDL lists the enum under `types`.
- Fixed-width `Option[T]` — a tag byte plus the inner value always reserved (`1 + sizeof(T)`). `None` clears the tag; assigning `T` sets it. `.is_some` and `.value` read it, and `.value` on a clear tag aborts with 1012. The IDL type is a defined struct (`OptionU64` with `tag` then `value`), not Anchor's short `option` encoding, so later fields stay put. Instruction arguments use the same layout. The client packs `None` as a zero tag plus zero bytes, and `0` as a set tag.
- Fixed-width `FixedString[N]` — a `u32` byte length plus `N` reserved bytes (`4 + N`). A string literal is stored only by `account.field = "..."` or `name: FixedString[N] = "..."`. `len` reads the stored byte count. A length past `N` aborts with 1013. The IDL type is a defined struct (`FixedString8` with `len: u32` and `data: u8[N]`), not Anchor's short `string`, so later fields stay put. The client packs `str` and rejects text that does not fit.
- Plain helper functions — an undecorated `def` with a return annotation. Calls are inlined (`do { ... } while (0)`), so `require` and checked math still abort the instruction. A helper is not an instruction: no discriminator, no IDL entry, no dispatch row. Recursion and a call chain deeper than 8 are rejected. Parameters are integers, bool, Pubkey, unit enums, `Mut` / `Account`, or `Signer`. `Init` and `Option` / `FixedString` parameters stay out of this cut.
- Nested `@struct` — fixed-width data packed inline in an account (or in another struct), with no discriminator of its own. `spot.origin.x` reads and writes the leaf at the summed offset. A whole struct copies onto another field of the same struct. The IDL lists the struct under `types` (`{"defined":"Point"}`). The client decodes it to a dict. A struct is not an instruction argument, a local, or an account. A cycle is rejected. `Option` of a struct and `Vec` stay unsupported.
- Account constraints on an instruction parameter, checked before the body. `Seeds[Init[T], "box"]` sets the PDA seed (one literal, letters digits or `_`). `HasOne[Mut[T], "field"]` requires that Pubkey field to equal the earlier account of the same name. `Address[Mut[T], expected]` compares the account key to a `Pubkey` argument. `Owner[Mut[T], program]` replaces the "owned by this program" check. `CloseTo[Mut[T], dest]` moves lamports to `dest` after a successful body, zeroes the account, and assigns it to the system program. A failed constraint aborts with 1014. `Executable` and `Ata` stay out.
- Aliasing refusal peels one constraint wrapper, so `HasOne[Mut[T], ...]` and `Seeds[Init[T], ...]` still count as mutable views. Two mutable views of the same account in one instruction stay `PS3000`. A second `Init` of that account, including under `Seeds`, stays `PS3001`.
- `@event` and `emit(Name(...))`. Fields are integers, bool, Pubkey, or unit enums, packed after `sha256("event:Name")[..8]`. The program logs that slice with `sol_log_data`. The IDL lists the event. The client `decode_event` reads one log payload. An event is not stored in an account. A payload over 1016 bytes is rejected.
- `system_transfer(src, dest, lamports)` is a System-program Transfer CPI (tag 2). `src` and `dest` are a `Signer` or a `Mut` account and must differ. The generated client marks those accounts writable and appends the System program. The counter client's `increment` does not.
- SPL token CPI. `TokenAccount` is a writable account with no owner or discriminator check. `TokenMint` is read-only. `token_transfer(src, dest, authority, amount)` is SPL Token instruction 3. `token2022_transfer` is the same call against Token-2022. `ata_create(payer, ata, owner, mint)` is associated-token CreateIdempotent (data byte 1) for the legacy token program. The client appends only the programs that call needs. These calls belong in an instruction, and a token source and destination must differ. The counter client stays free of token program constants.
- Multi-file programs. `from sibling import Name` is allowed when `sibling.py` is next to the file being checked. The compiler reads and parses that text; it does not import or execute it. Stdlib and third-party imports stay rejected. A sibling's accounts, errors, enums, structs, events, and helpers join the program. An instruction joins only when a loaded file imports it by name. A file can use a foreign name only after importing it. `pythsol check` and `pythsol build` pick up those siblings automatically.
- `examples/vault` and `examples/escrow`, also available as `pythsol init --template vault|escrow`. The vault PDA takes lamports with `system_transfer` and returns them on `close`. The escrow funds one PDA deal (`make`), pays the maker and closes to the taker (`take`), or closes back to the maker (`cancel`). The seed is one literal, so each program has one such account.
- Build cache. The key is the generated C, the package version, the clang version, the SBF arch, the runtime header bytes, and the flavor `sbf-o2-gc-strip-v1`. A hit copies the `.so` and skips clang. The manifest records `cache` as `hit`, `miss`, or `off`. `PYTHSOL_NO_CACHE=1` turns it off. `PYTHSOL_CACHE` (or `PYSOL_CACHE`) picks the directory; otherwise it is `%LOCALAPPDATA%/pythsol/cache` on Windows and `~/.cache/pythsol` elsewhere.
- `pythsol test` builds the program from `pysol.toml` (or `--program`) and runs pytest. The plugin fixtures are `svm`, `program`, `payer`, `accounts`, and `send`. `Init` accounts and a single `bump` are filled in. `expect_error` checks a custom error (`6000 + index`). Template tests shipped by `pythsol init` use only those helpers. `--localnet` deploys with `solana program deploy` when that CLI exists; the fixtures stay on LiteSVM. The pytest entry point is `pythsol = pythsol.testing.plugin`.
- IDL `metadata.pythsol.cpi` records, per instruction, whether the client should append System, Token, Token-2022, or the ATA program, and whether an init instruction pays. Account metas stay unchanged when they have no constraint. `pythsol client program.json` builds solders instructions from that IDL. `pythsol cpi` writes the same builders with a header that says a generic on-chain invoke is not lowered.
- `pythsol port IDL.json` writes a skeleton. Instruction bodies are `pass`. `Seeds`, `HasOne`, `CloseTo`, `Owner`, and `Address` are recovered when the IDL says so. Option and FixedString structs become `Option[T]` and `FixedString[N]`.
- `pythsol deploy` shells out to `solana program deploy`. `--dry-run` prints the argv and an estimated rent (`size * 6960` lamports) and does not look for the Solana CLI. Mainnet is refused without `--yes`, including a dry run. `pythsol faucet` calls `requestAirdrop` for at most 5 SOL and refuses mainnet. `pythsol wallet new` writes a Solana keypair JSON and calls `chmod 0600`. The secret is printed only with `--show-secret`.
- `pythsol verify --left A --right B` exits 0 when the sha256 matches and 3 when it does not. `pythsol profile` parses `consumed N of` and `(file.py:line)` from a log. It does not invent per-line compute units. `pythsol idl-publish --dry-run` writes the IDL and prints `anchor idl init`. Without `--dry-run`, a missing `anchor` binary exits 1 after the file is written.
- `pythsol serve` listens on `127.0.0.1:8765` (also `localhost` and `::1`). `GET /` is a check, emit, and compile page. `POST /v1/check` and `POST /v1/emit` run the compiler on the posted source. `POST /v1/compile` runs clang on the generated C when the SBF tools are installed and returns the `.so` as base64. Bodies that contain a keypair, seed phrase, or mnemonic are rejected. The page does not run user code. There is no hosted compile service.
- `Vec[T, N]` is a fixed-capacity field: a `u32` length plus `N` reserved scalar slots. `len` reads the length. Storing at the current length grows it. `Vec[T]` without a capacity is still rejected.
- Data enums mix `Name = index` with `Name: u64`. The wire form is the tag byte plus the payload width reserved for every variant, so the next field does not move. `.value` reads and writes that scalar and aborts with 1011 when the tag has no payload. A data enum is an account field, not an instruction argument.
- `system_transfer` from a program PDA debits that account and credits the destination directly (`rt_move_lamports`). The System program's Transfer instruction refuses an account that carries data. A transfer from a `Signer` is still a System CPI.
- Docs scaffold: `web/docs` (Astro 7.4.4, Starlight 0.42.7), light-only `web/shared-tokens/tokens.json`, `docs/gallery/index.json` for counter, ledger, vault, and escrow, short guides under `docs/guides/`, and `contrib/vscode` which maps `pythsol check --json` into editor diagnostics. No Lighthouse score, no hosted playground, and no package publish in this change.

## [0.1.0] — 2026-10-30
### Added
- Phase 3 — compiler back-end: `compiler/model.py` (IR-free `ProgramModel` with Anchor discriminators/packed Borsh layouts/`6000 + index` error codes), `compiler/emit.py` (C emitter lowering role checks, PDAs, System CPIs, `require`, checked arithmetic, dispatch table), `compiler/pipeline.py` (`emit_program`, `PS4xxx`/`PS5xxx` diagnostics), and `compiler/idl.py` (deterministic Anchor-legacy IDL + structural validator).
- Phase 3 — `pythsol build PROGRAM.py`: native SBF `.so` + generated C + IDL + `manifest.json` (sha256 hashes, toolchain info); byte-deterministic output verified by two-build tests.
- Phase 3 — the SBF runtime `src/pythsol/runtime/pythsol_rt.h`: zero-copy input decoder, Borsh readers/writers, checked arithmetic, PDA verification with the `ProgramDerivedAddress` domain suffix, C-ABI `sol_invoke_signed_c` CPI wrappers, and `rt_fail_log` `(file:line)` attribution — all pinned by ADR-0010 after empirical verification (LiteSVM + agave 1.18.26 sources).
- Phase 3 — acceptance harness `tests/test_phase3_litesvm.py`: counter initialize → increment(5) = 5; unauthorized increment fails `Custom(6000)` with `(counter.py:51)` log; overflow increment aborts at `(counter.py:52)` with no side effects. Plus model/IDL/emit/build unit and negative suites (PS4001/PS5003).
- Phase 0 — repository skeleton, Apache-2.0 license, contributing/code of conduct/security docs, [ADRs](docs/decisions/), `pyproject.toml` with hatchling/ruff/mypy, GitHub Actions `lint` + `unit` CI.
- Phase 1 — `pythsol.compiler.toolchain`: Agave/Anza platform-tools discovery (`PYTHSOL_SBF_SDK`, default cache path), sbpf compile/link flag helpers derived from `anza-xyz/rust@3175de2636 sbf_base.rs`, `compile_to_sbf` helper, plus `pythsol doctor` (Python, platform-tools, clang/lld sanity, `solana` CLI, `cargo-build-sbf`, keypair presence, optional RPC check) with `--json` and fix commands.
- Phase 1 — SBF spike C source at `Spikes/c/hello.c` and LiteSVM runner `Spikes/python/cn_litesvm_hello.py` gated behind the `toolchain` pytest marker.
- Phase 2 — compiler front-end pipeline `parse → subset → resolve → typecheck` in `src/pythsol/compiler/`, each stage emitting positioned `PSxxxx` diagnostics (`PS1000`–`PS3001`, `PS9000` internal-error guard). Random-AST fuzzing (`tests/test_phase2_fuzz.py`) proves stages answer every malformed input with diagnostics, never exceptions.
- Phase 2 — `pythsol check PROGRAM.py` CLI (exit codes 0/1/2) with `--json` machine payload; typed DSL surface (`Mut/Init/Account`, `FixedArray/Vec/Option`, `require`, `@instruction/@account/@error`) checked clean under `mypy --strict`.
- Phase 2 — the `examples/counter` program and a negative-fixture suite (`tests/test_phase2.py`) with ~60 rejected programs pinned to exact `code:line:col`.
- Docs — `docs/architecture.md`, starter ADRs under `docs/decisions/`.
